# Inateck BCST-47 Bluetoothスキャナ

## SDKの準備

Inateckの公式iOS SDKはリポジトリへ再配布せず、実機ビルドの前に固定コミットから取得します。

```sh
./ios/scripts/bootstrap_inateck_sdk.sh
```

スクリプトは `03aa36d0e204997130afaca00c2176aa7e5089af` を取得し、framework本体のSHA-256を検証して `ios/Vendor/Inateck` へ配置します。このディレクトリはGit管理対象外です。公式リポジトリにライセンスファイルが見当たらないため、App Store配布やバイナリ同梱の前にInateckへ再配布許諾、正式ライセンス、現行SDK、XCFramework提供可否を確認してください。

SDKのframework本体はarm64のiPhoneOS用です。Simulatorビルドでは `INATECK_SDK` を定義せずframeworkもリンクしないため、アプリ内モックを使用します。

## Simulatorでの確認

Simulatorは独立したBluetoothペアリング先ではなく、Inateck SDKによるBCST-47の検索・接続は検証できません。macOSへHID接続したスキャナのキー入力がSimulatorへ流れる場合もありますが、このアプリのSDK接続経路の合否にはなりません。

1. 設定タブの「Bluetoothスキャナ」で「スキャナを検索」を押す。
2. `BCST-47 (Simulator)` を選び、接続済み表示を確認する。
3. 照合セッションを開始し、「入力元」でBluetoothが自動選択されていることを確認する。
4. 「カメラなしで判定をテスト」を開き、「モックQR」、「モックCode 128」の順に押す。
5. 照合結果と履歴件数を確認する。

UIテスト向け起動引数 `-demoBluetoothConnected` を指定すると、モック端末を起動時から接続済みにできます。

## iPhoneとBCST-47での確認

1. Mac側でBCST-47の接続を解除するか、MacのBluetoothを一時的にオフにして自動再接続を止める。
2. リポジトリルートで `./ios/scripts/bootstrap_inateck_sdk.sh` を実行してから、XcodeでiPhone実機へインストールする。
3. 初回起動時にBluetooth利用を許可する。
4. 設定タブの「初回接続ガイドを開く」を押し、画面に表示される設定用Code 128を次の順に1回ずつ読む。通常表示で反応しない場合は「全画面で大きく表示」を押し、iPhoneを横向きにして長辺いっぱいのコードを読む。
   1. 設定を開始: `/*EnterSet*/`
   2. GATTモードへ切り替え: `/*BLE_GATT*/`
   3. 設定を保存して終了: `/*ExitSave*/`
5. スキャナ画面に `BLE_GATT` と成功表示が出たことを確認し、ガイド末尾の「スキャナの検索を開始」を押す。iOSのペアリング確認が表示された場合は「ペアリング」を押す。iPhoneの設定アプリから先にペアリングしない。
6. 検出されたBCST-47を選んで接続する。
7. 設定タブの「スキャナを切断」を押し、iOS側のリンクが残ったままでも「以前接続したスキャナ」に端末名が表示されることを確認する。
8. 「別のスキャナを検索」で0件になっても既知端末が消えないことを確認し、「（端末名）に再接続」で電源OFF／ONなしに接続できることを確認する。
9. 照合画面でBluetoothが自動選択されていることを確認し、実ラベルのQR、Code 128の順に読む。
10. 一致、不一致、同一品番の連続箱、履歴保存を確認する。
11. カメラへ戻し、現在ステップに対応したカメラ読取が再開することを確認する。
12. Bluetooth読取中にスキャナの電源を切り、読取済みQRを保持したままカメラへ戻ることを確認する。
13. スキャナを再起動し、アプリのバックグラウンド復帰または再起動で最後の端末へ自動再接続することを確認する。
14. QR待機中はCode 128が照合画面へ反映されず、QR読取後のCode 128待機中はQRが反映されないことを確認する。
15. QRを読み取った直後に同じQRを連打し、その後にCode 128を読み取っても、通知が止まらず照合を完了できることを確認する。
16. 手順15を20回以上繰り返し、QRからCode 128への工程変更時に「スキャナーの読み取り種類を設定しています…」が再表示されないことを確認する。
17. Code 128待機中にアプリを強制終了して再起動し、再接続時に変更前の全バーコード設定が復元されてからQR待機へ切り替わることを確認する。
18. セッション終了後、Code 128以外も含めた全バーコード種類が照合開始前のON／OFFへ戻ることを確認する。
19. Bluetooth接続済みのままカメラへ切り替え、背面映像が表示された状態で照合セッションを終了する。
20. 終了ボタンが一時的に「終了中…」となり、カメラ停止完了後に画面が閉じることを確認する。
21. 直後にiPhone標準のカメラアプリを開き、背面映像とタップフォーカスが正常であることを確認する。
22. DeviceHub／AirPlay等の画面ミラーリングを終了した状態で手順19〜21を20回以上繰り返し、CodeMatchと標準カメラのどちらにも黒画面が発生しないことを確認する。
23. 画面ミラーリング中にカメラを開始し、マルチタスクカメラ非対応端末では開始せず、ミラーリング終了を案内することを確認する。
24. カメラ稼働中に画面ミラーリングを開始し、カメラが自動停止して同じ案内を表示することを確認する。

スキャナが接続済みの間は、照合の開始、「次のコードを照合」でQRに戻るとき、照合タブ・アプリ前面への復帰のたびにBluetoothが入力元になります。読み取り設定中もカメラへは切り替えず、Bluetoothのまま「設定しています」と表示します。利用者がカメラを選んだ場合はその1箱（QRの読み直しを含む）の間だけカメラを使い、次の箱からBluetoothへ戻ります。Bluetooth読取中の切断や読み取り設定の失敗では現在ステップを保持してカメラへ一時的に退避し、再接続・設定完了でBluetoothへ自動復帰します（#145）。

照合中は`getSettingInfo()`で実機が報告した全バーコード種類とON／OFFを保存し、セッション開始時にQRとCode 128の両方だけを有効にします。QR待機、Code 128待機、結果表示、次の照合の間ではGATT設定を書き換えず、読取順序とデータ形式はアプリ側で検証します。カメラへの切替、バックグラウンド移行、セッション終了・切断では保存値をそのまま書き戻します。SDKの設定完了通知が3秒以内に返らない場合は新しい設定コマンドを重ねず、安全のためカメラへ退避してリンクを再接続します。異常終了やタイムアウト時に制限がスキャナへ残っても、保存したスナップショットを次回接続まで保持して復元します。スナップショットはスキャナごとに保存するため、照合中に電源が切れたスキャナの復元待ちが残っていても、別のスキャナを接続して照合を続けられます。元のスキャナは次に接続したときに復元します（#135）。新しい制限を開始するときは実機から取得した最新設定を必須とし、古いキャッシュだけから変更前設定を推測しません。

固定している公式SDKには、Code 128だけの信頼度しきい値や認識精度を数値指定する公開APIはありません。このアプリでは、照合セッションの開始時にSDKが報告したQR・Code 128以外のバーコード種類を無効化し、不要な候補判定を減らします。

GATT以外のモードのまま接続したスキャナは、アプリがGATTモードへ切り替えて再起動します。機種によっては再起動後に広告名と識別子が変わる（例:「Hyper 160B-4F5F-UNI」→「HPRT-4F5F」）ため、アプリは再検索して名前の末尾4桁が同じスキャナへ接続し直します。見つからないときは「スキャナを検索」から選び直すよう案内します（#134）。

同時に使うスキャナは1台です。設定画面で別のスキャナを選ぶと、前のスキャナへの自動再接続や検索、接続中の試行を打ち切って選んだスキャナへ接続し、以後はそのスキャナを自動再接続の対象にします。接続中でも別のスキャナの行と検索ボタンは押せます（#137）。

発見できない場合は、まず「以前接続したスキャナ」から直接再接続します。初回接続または保存済み端末がない場合は、Macやほかの端末との接続が残っていないか、BCST-47がHIDモードではなくGATT／APPモードかを確認し、Inateck公式アプリでも接続可否とファームウェア要件を確認します。

バックグラウンドでの読取は対象外です。アプリがフォアグラウンドにある間だけ使用し、`bluetooth-central` background modeは有効にしていません。

照合セッション終了時は、カメラの停止が完了してから画面を閉じます。`AVCaptureSession`はアプリ内で再利用し、照合のたびにカメラパイプラインを破棄・再生成しません。QR／Code 128の認識には720pを使用し、カメラデーモンのバッファ負荷を抑えます。iOS 18以降では対応端末のマルチタスクカメラアクセスを有効にします。画面がミラーリング／収録中で、端末がマルチタスクカメラに対応しない場合は、標準カメラまで停止するOS不具合を避けるためカメラを開始しません。終了処理中に画面が短時間待機することは正常ですが、数秒以上続く場合はXcodeログの `[CameraScanner] Stopped session in ...s`、`Capture environment screenCaptured=... multitaskingSupported=...`、`Multitasking camera supported=... enabled=...`、`format=...` とiPhoneのカメラ使用中インジケータを記録してください。
